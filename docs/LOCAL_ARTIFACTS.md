# Persistent local artifact adapter

`LocalEncryptedArtifactRepository` in `apps/api/src/local-artifacts.ts` implements the existing artifact `put`/exact-receipt `get` contract for a dedicated POSIX development directory. It uses the same identity-bound authenticated `MGART001` envelope as the cloud adapter, with a caller-owned key provider. Filenames and MIME metadata are inside the encrypted payload. It does not configure AWS, scanning, document authorization or a production storage service.

Construct it with an absolute `rootDirectory`, a `keyManagementProvider`, and an optional deadline of at most 60 seconds. The parent directory must already exist and be trusted operator configuration. The adapter creates private owned directories and regular files, rejects observed symlinks and unsafe permissions, bounds ciphertext reads, and publishes a fully written/fsynced staging file with an exclusive hard link. It does not overwrite an existing artifact identity.

Receipts use `local-v1-<ciphertext SHA-256>` as the object version and a matching quoted local ETag, plus the existing checksum and size fields. These are exact-content references, not AWS version IDs or a substitute for encryption authentication. Persist the receipt in the authorized encrypted document manifest. A read must supply that exact receipt and identity; the envelope is authenticated before plaintext is returned. Reopening the repository over the same directory and key provider can recover it without process-local object maps.

Repeating a put under the same identity authenticates the existing and proposed content. Identical bytes and metadata return the original receipt; changed content or metadata fails explicitly. After an interrupted/unknown write outcome, preserve the original identity and retry the same content to recover its receipt. Use a new artifact identity for a new document version. Do not delete or replace a published object to force a retry through.

Each repository instance admits one active operation, including underlying provider work that ignores a cancelled caller. Close rejects new work, aborts the active caller and waits for owned cleanup. A noncooperative provider can therefore delay close; the adapter cannot terminate arbitrary external transports. Owned key buffers and late plaintext results are cleared where available. Caller-owned inputs and the borrowed provider remain the caller's responsibility; this is not a process-memory erasure guarantee.

Node filesystem path APIs cannot defend against an adversary with the same OS identity concurrently renaming ancestor directories. The root and parent are trusted configuration, and a dedicated OS account is needed when that isolation is part of the threat model. Network filesystems, Windows filesystems, full-machine power-loss recovery, managed key rotation, retention cleanup, quotas and multi-instance capacity have not been qualified. Tests use temporary local directories and generated data.

This adapter is not selected by `npm run dev:api`; that entry point still uses its existing quarantined upload store. The [Canvas composition factory](RUNTIME_COMPOSITION.md) can borrow this adapter, but operator bootstrap and a real isolated source scanner are still required before user uploads become inspected assignment sources.
